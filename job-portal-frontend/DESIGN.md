# OfferPilot 前端设计约定

## 产品与页面方向

OfferPilot 是求职者管理岗位投递与简历的工作台。申请人看板优先支持快速扫描、上传和状态确认，不采用营销式大标题、装饰动画或数据大卡。现有“岗位机会”是默认页；“我的简历”通过同级页签进入，切换时保留岗位数据与操作状态。

## 布局与视觉

- 复用 `index.css` 的暖白画布、深色文字及蓝/绿/橙 token；蓝色用于交互与处理中，绿色仅表示成功，橙色用于历史提醒，红色用于失败。
- 桌面端简历页限制为 980px：紧凑上传栏在前，纵向记录列表在后。记录以分隔线维持信息关系，不叠加大阴影卡片。
- 标题、正文与元数据沿用 Poppins / Inter / Segoe UI 回退；文件名允许安全换行，canonical MIME 显示为 PDF/DOCX（原值仅保留为辅助提示），解析文本保留换行并在区块内部滚动。
- 状态标签同时提供文字，不只依赖颜色。按钮沿用 Bootstrap 与现有 accent 类，焦点复用蓝色可见轮廓。

## 组件行为

- 上传控件使用真实标签并持续显示格式和 5 MiB 限制；校验、成功、错误和后台解析状态通过 `status` / `alert` 与 `aria-live` 呈现。
- 列表首屏只取元数据。仅在用户展开成功记录时加载解析文本；下载和详情操作分别显示进行中状态并阻止重复触发。
- 岗位匹配作为同一简历记录内的次级明细按需加载和缓存，不嵌套新卡片。百分比使用蓝色信息强调；已匹配技能用绿、待补技能用橙，并始终保留文字标签。不可比较的岗位显示明确文案，不把空分数呈现为 0。
- `QUEUED` / `PROCESSING` 每 2 秒链式刷新；请求不重叠，失败即暂停并提供手动恢复，组件卸载时清理计时器。

## 响应式

- 768px 以下上传区和记录转为单列，页签保持等宽且触控高度不低于 44px。
- 记录操作在中等窄屏并排，440px 以下转为纵向；元数据由三列依次降为两列和单列，页面不产生横向溢出。
