# OfferPilot 前端设计约定

## 产品方向

OfferPilot 是求职者与招聘管理员共用的工作台。求职者需要比较真实岗位、确认投递状态并管理简历；管理员需要快速查找岗位、投递与用户记录并完成操作。界面采用清晰、克制的工具型设计：任务内容优先，品牌表达集中在登录与注册页，不使用营销数据、虚构字段或装饰动画。

## 基础视觉

- 页面画布使用中性灰白 `#f4f6f5`，内容面使用纯白，细边框 `#dce3e1` 表示分组；输入与选择控件使用对比度达到 3:1 的 `#7c8b86` 边界。阴影仅用于认证容器、表单和弹窗等有明确层级的区域。
- 品牌与主操作使用深青 `#176b64`，悬停使用 `#105b55`。普通文字为 `#182220`，次要文字为 `#52605d`。主按钮白字与深青背景保持清晰对比。
- 信息、成功、提醒、失败和中性状态分别使用蓝、绿、棕黄、红和灰的小型文字标签。状态必须同时显示文字，不能依赖整张记录的背景色。
- 字体使用 Microsoft YaHei、PingFang SC、Noto Sans CJK SC、Segoe UI 和系统无衬线回退，不请求外部字体。中文标题不使用负字距或强制英文大写。
- 以 4 / 8 / 12 / 16 / 24 / 32 为主要间距尺度。按钮和输入控件最低高度为 44px；正文行高约 1.65，工具信息约 1.4–1.55。
- 按钮、输入框与链接必须有可见键盘焦点。所有长标题、邮箱、公司、文件名和错误代码允许安全换行；遵守 `prefers-reduced-motion`。

## 组件与布局

### 登录与注册

桌面端为品牌信息区与表单区双栏布局。桌面最大宽度约 1200px、高度至少 690px，左右比例 40:60；品牌区以 O 环形标志、OfferPilot、求职管理平台、短分隔线及两行真实介绍垂直居中。只使用几何圆装饰；表单区突出邮箱登录或注册主操作，Google 登录使用描边次操作。窄屏转为上下布局，品牌区压缩为紧凑头，保留真实产品介绍和完整表单标签，注册主操作保持在首屏内。登录与注册共享 AuthBrand / AuthInput / Icon；字段左侧统一线性 SVG，密码和确认密码有独立的显示/隐藏按钮，切换保持输入值和焦点。

### 导航与工作区

导航横排 O 环标志、OfferPilot、实际角色工作台链接和真实用户。用户菜单只提供已有的退出登录，支持点击、Tab、向下箭头打开、Escape 关闭并返回焦点、外部点击与焦点离开关闭。长用户名称在导航省略以保护布局；390px 下品牌与用户同排、工作台链接第二排。工作区使用稳定的页面标题、页签、工具栏、结果记录层级。

### 岗位与后台记录

- 求职页以约 160px 高浅青欢迎横幅和图标下划线页签开头。开放岗位独立白底容器内排列细边框岗位行，左侧通用岗位图标及真实标题、公司、完整描述，中部真实时间，右侧状态与合法操作。底部展示六种真实状态图例。没有虚构薪资、城市、部门或职类图标。手机端转为单列并保留全部内容。
- APPLIED 柔蓝、ACCEPTED 柔绿、REVIEWING 棕黄、REJECTED 柔红、WITHDRAWN 中性灰，未投递使用空心中性灰点。未投递可立即投递，APPLIED 只能撤回，WITHDRAWN 可再次投递，其余状态只显示状态与说明，不渲染操作按钮。
- 后台岗位、投递与用户均使用紧凑记录列表。搜索和筛选保持在结果之前；分组展开、状态更新、编辑、关闭、开放、删除、停用确认等原行为保持不变。
- `job-card`、`application-card` 与原状态 class 继续作为状态和测试契约。状态 class 只决定标签颜色，不给整张记录铺色。
- 投递状态编辑区在桌面端保持标签、下拉框、保存按钮同排：标签与按钮禁止压缩，下拉框允许收缩；窄屏依内容转为单列。
- 空状态说明当前没有结果和可采取的下一步。加载、数据请求错误与业务操作错误分开表达，重试只针对数据加载。

### 简历

简历工作台与岗位工作区同宽，浅青虚线边框上传区使用真实文件输入（视觉上由"选择简历文件"按钮触发），并持续显示已选文件名、PDF / DOCX 与 5 MiB 限制。记录沿用纵向分隔结构，文件名、解析状态、元数据和操作有清楚层级。

仅在展开成功记录时加载解析文本与岗位匹配；保留下载、轮询、失败暂停、手动恢复和重试行为。岗位匹配仍是 23 个有限技术关键词的规则覆盖率，同时展示命中与待补技能和边界说明，不宣称 AI 评估或录用概率。

## 响应式与验证

- 900px 以下认证页转为上下布局，岗位记录先变两栏；600px 以下岗位变单列。768px 以下管理记录、上传区和简历记录转为单列。600px 以下后台四页签采用 2×2，不截断功能名称。
- 600px 以下导航改为两行，岗位状态与操作同排、提示独占下一排；页面不能产生意外横向滚动。
- 代表性验证使用 1440px 与 390px，覆盖长岗位名、长公司、长邮箱、长文件名、全部状态、文件输入及后台状态保存。静态截图之外，还需以单元/集成测试验证原 API、认证、页签键盘行为、确认弹窗与简历交互。
