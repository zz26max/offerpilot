# OfferPilot 前端 UI 改进方案

日期：2026-10-01。流程：竞品调研 → 现状诊断与方案 → 实现、审查和验证。

## 目标与边界

OfferPilot 面向求职者和招聘管理员。求职者的主任务是比较岗位、确认投递状态、管理简历；管理员的主任务是查找记录并完成岗位、投递和账号操作。此次改造提升阅读层级、布局一致性、手机可用性与状态反馈。

保留现有路由、认证与会话行为、API 路径/方法/参数/请求头、Redux 数据和业务权限。后端、数据库与接口配置不在修改范围内。岗位目前只有名称、公司、描述和日期等字段，不能照搬竞品的薪资、地点、经验、收藏、沟通或自动投递。简历结果仍是有限词典的规则技能覆盖率，不改变算法、不宣称 AI 评估或录用概率。

## 第三步：实施计划

1. 统一语义 token、中文排版、按钮/输入框/焦点/表面/边框；更新既有 `job-portal-frontend/DESIGN.md`，规则必须落实到样式。
2. 优化登录与注册的品牌侧栏、表单阅读顺序和主次按钮；保留账号提示、Google 跳转、校验和消息。
3. 修复移动导航；优化求职者岗位记录的层级及状态展示，保留投递、撤回、再次投递与键盘页签行为。
4. 管理员各页面统一标题、筛选工具栏、记录和表单；保留分组、展开/收起、全部筛选、编辑/关闭/开放/删除、状态保存、账号停用确认。
5. 简历页沿用上传栏和记录结构，优化视觉细节；保留格式限制、轮询、错误重试、详情、下载与匹配边界。
